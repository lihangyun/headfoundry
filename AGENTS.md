## Failed-route cleanup is required before the next route

User instruction,2026-10-20:do not accumulate failed experiment code,tests,
generated heads/renders,predictions,third-party frameworks,weights or environments.

1. Close the bounded experiment honestly:record method,main variable,input/model
   identities,budget,actual errors,failed gates and stop condition in docs. Never
   turn a technical test pass into reconstruction or likeness acceptance.
2. Before deletion,check Git status,actual resolved targets and running jobs.
   Never delete original authorized inputs,consent/provenance,accepted baselines,
   unrelated edits or shared evaluation/safety code merely because a fit failed.
3. Keep a small private evidence archive with reports/controls and at most a few
   representative images. Keep experiment docs and a source Git recovery ref.
   No need to retain every failed binary or reproduce all historical images on
   disk. Explain that deleted public weights need redownloading and generated
   binaries need rerunning;the compact archive is not a full binary backup.
4. Remove failed-route-only runners and tests from the active tree. Retain
   generic numerical/rights/safety regressions and successful evaluation fixtures.
   Remove exclusive model/source downloads,caches and environments;do not blindly
   uninstall shared dependencies. Confirm callers before removing anything.
5. Verify the archive,original-input integrity,remaining tests and no dangling
   live imports. Record actual deleted bytes/files,remaining exceptions and
   recovery limits,then make a focused local Git commit. Do not push private data.
6. Only after that closeout begin a different route. Do not reactivate a rejected
   route without a documented materially different hypothesis and a new bounded
   pre-registration. No checkpoint/threshold/precision sweep to rescue failure.
